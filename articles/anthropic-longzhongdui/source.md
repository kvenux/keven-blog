# Anthropic 的隆中对：长期主义的五年复利

![Anthropic的隆中对](assets/00-cover.png)

2026 年 10 月中旬，Anthropic 的一份内部文档在 X 上引起热议。这份《Concise Research Roadmap》由联合创始人 Jared Kaplan 撰写，正文三页，附有 Dario Amodei、Tom Brown 等十几人的 24 条批注，随 Bartz 诉 Anthropic 版权案公开，一直留在法院案卷里。

让人惊叹的是它的成文时间：2021 年 7 月。那时 GPT-3 的上下文窗口只有 2048 个 token；最强的代码模型 Codex 在 HumanEval 上只能解对 28.8% 的题；GitHub Copilot 刚开放预览，AI 写代码还停留在补全下一行。成立不到半年、还没有产品的 Anthropic，在这时把通向 AGI 的第一站定为一个具备**all the capabilities of a software engineer colleague**的 AI 助手。评审批注里，Dario 已经在担心**tools that execute code at deployment time**。

![2021年7月，Anthropic团队围绕三页路线图的评审会（据法院公开文档绘制的示意）](assets/01-roadmap-review.png)

五年后，路线图上的规划正一项项成为现实。Claude Code 在陌生代码库里自己搜索、修改、运行代码，执行每条命令前先做权限检查；Opus 5.5 在终端编程评测 Terminal-Bench 4.0 上拿到 66.4%，领先同期竞品。Anthropic 在 coding 领域站到了最前面。X 上的评论大多是同一句话：**2021 年就知道全部了。**

眼光准，执行也没走样。这份路线图凭什么一路兑现？

本文的回答是：路线图把第一站放在了一个对错能被机器判定的领域。同一种对错判断，在训练时是奖励信号，在使用时是 Agent 自我纠错的依据。Anthropic 五年的投入都围绕这一点展开，形成了一个越用越强的闭环。这是复利的来源。

## 一、路线图写了什么

路线图由两部分组成：Jared Kaplan 撰写的正文，定下目标和手段；7 月 16 日下午评审会上的 24 条批注，补充了团队对具体问题的预判。

### 正文：目标与手段

- **长期目标**：**safe, beneficial AGI**。
- **主要目标**：作为 proof of concept，做出**a general AI assistant that can interact conversationally with a user to create, edit, and explain software**，最理想的版本具备**all the capabilities of a software engineer colleague**。文档承认短期内达不到，但所有研究项目都被看作在构建这个**proto-AGI**的某个方面。
- **实现路径**：**large generative models with long memories, fine tuned via RL using both automated rewards and human feedback**。
- **具体手段**：
  - **数据**：预训练 language+code 模型，研究**1T and larger**模型的训练；数据集覆盖 code、diffs、PRs、debugging 和对应的 code evaluations；用 Diffs、PRs、Wikidiffs 微调，**connect human intentionality to model behavior**。Dario 在批注里补充了**stackoverflow, issues, comments**。
  - **工具使用**：用 RL 训练模型使用工具，先在**search, printf debugging**上看到**clear signs of life**；寻找**more favorable scaling with training compute as compared to supervised learning**的训练方法。
  - **算力**：提前**de-risk future hardware such as TPUs, Trainium**，**prepare for compute deals**。

### 批注：两个预判

1. **编程助手的第一个能力，是读懂陌生代码库。** Tom Brown 认为**repository browsing**是最好的起点；Nelson Elhage 说，如果只能给 Copilot 加一个能力，就是**go look up my project's type definitions**；Ben Mann 补充，**especially for a repo you've never seen before**。
2. **Agent 的头号难题，是执行代码的安全。** Sam McCandlish 问**how to deploy non-sandboxed tools safely?**，Dario 补充**tools that execute code at deployment time**。那时还没有任何 agent 产品。

## 二、战略思维的落地

路线图上的目标和手段，五年后一项项兑现了。要解释它凭什么能兑现，得先看清开头说的复利从哪里来。

复利的意思是：这一轮的产出，成为下一轮的投入。放在模型公司身上，就是这一代模型做出的东西，能变成训练下一代的燃料。这需要三个条件：能判断模型变好了没有；判断的成本低到能随算力放大；使用中能不断产生新的判断。第三个条件要分两步实现：使用时也能判断对错，判断的结果还要回到训练里。

在大多数领域，这三件事是分开的：训练靠人工打分，用户满不满意是另一回事。代码的编译器、测试和终端，提供了前两样，也让第三样有了基础。Anthropic 的路线图，正是沿着这三个条件落地的。

![复利需要三个条件：可度量、可规模化、可回流](assets/02-compounding-loop.png)

### 可度量：选 coding

复利的前提，是知道自己有没有变好。路线图的实现路径写了 automated rewards，代码正好满足：对错能由编译器和测试判定，模型在编程上的每一点进步都能被量化。

### 可规模化：让对错判断随算力放大

人工标注的速度跟不上算力增长，机器判定可以。对错能由机器判定，多投入的算力才能转化成能力。路线图要寻找**more favorable scaling with training compute as compared to supervised learning**的训练方法，说的正是这件事。

有了这个前提，算力才值得提前布局。路线图按**1T and larger**的规模做准备，当时引发轰动的 GPT-3 是 1750 亿参数；它还要提前 de-risk TPU 和 Trainium，后来 Anthropic 与谷歌、亚马逊的大规模算力合作，用的正是这两种芯片。

### 训练与使用同源：Agent 在终端里工作

模型变强之后，还要让它在使用中拿到同一种对错信号。路线图让工具使用从 search 和 printf debugging 练起，批注把读懂陌生代码库列为第一个能力，这些事程序员都在终端里完成。Claude Code 选择了命令行工具的形态，在终端里搜索、修改、运行代码。命令是否成功、测试是否通过，结果都写在输出里。

训练时用来打分的对错，在使用时成了 Agent 自我纠错的依据。

### 可回流：使用规模化，信号回到训练

回流的前提是用户敢用。Agent 要在用户的机器上执行命令，这正是 2021 年批注里 Sam 和 Dario 列为头号难题的那件事。Claude Code 执行每条命令前都要做权限检查，个人和企业才敢让它在自己的机器上运行。

使用有了规模，信号才能回流。2025 年 8 月，Anthropic 更新了个人用户条款：用户同意后，新的对话和 Claude Code 编程会话可以用于训练模型，理由之一是让未来的模型更擅长编程。真实任务里的对错，回到了下一代模型的训练中。

三个条件都满足，闭环才转得起来。2022 年底 ChatGPT 把行业焦点拉向对话产品，Anthropic 也推出了 claude.ai，模型迭代的重点仍然放在编程上。五年的投入都留在这一个闭环里，每一代模型都站在上一代的使用之上，这就是复利。

### 同样做代码，为什么是 Anthropic

一个自然的问题是：OpenAI 在 2021 年 7 月就发布了 Codex，GitHub Copilot 也是基于它做的，在代码领域起步更早。为什么复利的故事落在了 Anthropic 身上？

差别在于做成了什么。Codex 证明了模型能写代码，Copilot 把它做成了编辑器里的补全工具：人写一行，模型补一行。Anthropic 的路线图从一开始瞄准的，是一个能独立干活的同事：会用工具、读仓库、调试、验收，干活的结果再回到训练里。前者是一项能力，后者是一个能自我强化的闭环。

![同样做代码，补全是一项能力，同事是一个闭环](assets/03-copilot-vs-colleague.png)

另一个差别是聚焦。此后几年，OpenAI 的重心转向 ChatGPT、GPT-4 和多模态产品，Codex 模型在 2023 年停止对外提供，直到 2025 年才推出新的 Codex Agent。Anthropic 则五年都押在 coding 上。今天两家的差距已经在缩小，新版 Codex 在部分评测上追平甚至反超，但 Claude Code 的先发，正是这五年聚焦的结果。

## 三、源码里的闭环

从 2026 年 3 月泄露的 Claude Code 源码看，第二章说的闭环在产品一侧处处可见：Agent 在用户的机器上用同一种对错自我验收，问题按模型版本度量，使用中的信号被系统地收集起来，并为下一代模型留好了接口。

先交代三个概念。Claude Code 每次运行，都会先给模型一段很长的工作说明，也就是系统提示词，告诉它该怎么读代码、怎么改、怎么汇报。模型训练好以后，团队要修正它的某个行为，最快的办法是在这段说明里加一段针对性的要求，下文称为**补丁**。源码里，这些补丁旁边留着开发者的**注释**，写明为什么加、什么时候删。

![源码里的闭环：补丁从加上到删除的一生](assets/04-patch-lifecycle.png)

### Agent 自己验收

内部版本里，和用户对话的主代理可以调用另一个模型实例作为验证代理。验证代理只能读、不能改，它的任务是想办法把刚完成的实现弄坏。它判定通过，必须附上实际运行的命令输出；较大的改动要先过它这一关，主代理才能向用户报告完成。

验证代理依赖的，正是训练时 automated rewards 依赖的那种信号：命令输出和测试结果。

除了 Agent 自己判断对错，源码里还能看到一个从发现问题到交给下一代模型的循环。

### 员工先用

代码库里有几十处标记，标出每次换上新模型时必须检查和更新的地方，比如默认模型、上下文长度、是否开放自动模式。新模型上线后，最先用它的是 Anthropic 自己的员工。

Claude Code 会判断用户是不是 Anthropic 员工，员工和外部用户拿到的是两套不同的系统提示词，新的补丁先只放进员工那一套。员工遇到奇怪输出、选错工具、幻觉或拒绝，可以一键上报，也可以一键上传整段会话；员工表现出挫败情绪，系统也会记下来。外部用户的版本里没有这些功能。

### 按版本计数

源码注释记录，团队按模型版本测量同一种失败：声称完成，实际没完成，新模型要和上一代对比。员工的上报怎样汇总成这类指标，源码里看不全，但测量本身是确定的。

这个比例上升了，团队就在系统提示词里加一段补丁，要求模型如实报告：测试失败就贴出输出，不许压掉失败的检查来换取通过。提示词的其他修改也一样，注释里记着每次改动对应的假设和评测结果。

### 补丁推给用户

补丁在员工中验证有效后，再做 A/B 测试：一部分外部用户用加了补丁的版本，一部分用原版，比较效果，确认后推给所有人。

外部用户这一侧同样在被度量。会话按完成程度分类，摩擦被归为误解需求、方法错误、代码有 bug 等类型；用户说一句**keep going**也会被记下来，那是模型停得太早的信号。用户同意后，编程会话可以用于训练；用户主动分享的会话，按差评、好评、挫败打上标签。

### 补丁写好退役条件

补丁并不打算永久保留。源码里，补丁旁的注释写着退役条件：**等模型默认不再这样，就删掉**、**下一代模型发布时删除这一段**。补丁先替当前模型兜底，问题留给下一代模型在训练中解决，到那时补丁就可以删除，循环回到起点。

这些会话和问题怎样进入训练，源码里看不到。合理的推测是：带标签的失败会话和补丁记录的已知问题，就是下一代模型的训练目标；补丁被删除的时候，问题已经被模型吸收。

## 结语：从隆中对到汉中王

207 年，寄居新野、无地无兵的刘备，从诸葛亮那里得到一条路径：先取荆州、益州，再图天下。十二年后，他据有荆益，自立为汉中王。每一步都建在上一步的地盘上：有了荆州，才有入蜀的本钱；有了益州，才能北争汉中。

Anthropic 的五年也是这样，每一代模型都建在上一代的使用之上。2021 年的三页纸，就是它的隆中对。

这和外界对这家公司的印象很不一样。在不少人眼里，Anthropic 有点像一家**神棍公司**：X 上常有人把它叫作末日教，员工被描述成一群高智商的 doomer；Dario 则被批评高高在上，一边警告 AI 可能带来灾难，一边做最强的模型、拿最多的融资。这些批评有它的来由。可同一家公司，又用五年时间一步步执行一份三页纸的规划，从数据、算力到产品，几乎没有偏离。能把长期规划执行到这种程度的创业公司，并不多见。

被叫作神棍，某种程度上是长期主义的代价。按五年后的终点做规划，在当下的旁观者看来，难免像在说胡话。在一个追热点、比发布速度的行业里，Anthropic 能坚持下来，靠的不只是信念：路线图把第一站放在一个对错能被检验的领域，每走一步，都知道自己有没有走对。外界怎么评价，改变不了测量的结果。

这对公司和个人都是启示。浮躁的环境里，难的是在没有掌声的时候，继续做同一件事。长期目标定下之后，还要找到一种检验进展的方式：对公司，可以是一组持续跟踪的指标、一个被真实使用的产品；对个人，可以是一个能反复打磨的作品、一项能用结果衡量的技能。有了这把尺子，短期的喧嚣只是噪音，每一次投入都能留下来，成为下一轮的起点。
