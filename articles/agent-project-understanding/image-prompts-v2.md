位置：## 一、

生成横版16:9、高分辨率中文技术机制图，面向有技术背景的博客读者。纯白且完全不透明背景（#FFFFFF），不要透明PNG。风格是严谨的研究笔记 / 软件架构图 / 工程师细笔白板，不是儿童简笔画，不是科普卡通。采用极细深灰线条、细箭头、纤细清晰中文字体（接近细黑体或钢笔字），标题也不要粗黑马克笔。颜色仅用于关系编码：蓝色代表当前任务，墨绿色代表长期经验，赭红代表边界；色彩克制，仅10%区域有极淡背景。用真实关系节点、证据表、调用顺序、范围边界增加信息量。禁止大图标、芯片图标、大脑图标、书本、放大镜、人物、机器人、便签、荧光笔、立体阴影、气泡框、粗圆角彩色卡片、粗箭头、手绘爆炸形。画面利用率约80%，至少20%空间留白；主体字清晰，文字不相交。边框为纤细直角，结构像论文中精心设计的机制图，而非PPT堆框。逐字使用给出的中文，不能自由编数字或实验结论。
主标题：同一个项目，两种知识积累方式
副标题：共同依靠先验与代码证据，差异在项目经验如何留下来
布局：左Agent右人类，两列上下四层对齐，层次之间细横分隔，底部共同验证条，使用约18个短节点和有标签的关系。
顶层“已有知识”：左“跨语言、跨项目的通用先验”，下用小节点“缓存 / 认证 / 异步 / 数据访问”；右“通用知识 + 长期项目经验”，下用小节点“模块职责 / 执行顺序 / 历史故障 / 设计理由”。
第二层“任务进入”：两侧同一个细框“登录页面缓存是否隔离用户？”。左向下三分支“搜索相关文件”“读取当前实现”“追查跨文件关系”，汇聚下一层；右从经验节点向下两分支“激活相关关系”“缩小核对范围”，汇聚“读取当前实现”。所有流程箭头细，左标“现场恢复”，右标“经验指导”。
第三层“当前理解”：左一个明确蓝色边界窗口“本次上下文”，内部三个小节点“缓存键”→“身份读取”→“检查顺序”，下“形成当前任务的证据链”；右绿色关系图“更新后的项目认识”，同样三个节点，但增加“旧判断”到“新证据”再到“修正关系”的反馈小路径。两侧共同细条“结论仍需当前源码与测试证据支持”。
第四层“进入下一次任务”：左虚线从本次上下文指向“历史上下文 / 外部记忆”再到“下一次任务”，线上标“显式保留与检索”；边上小字“普通会话不自动更新权重”。右从更新模型回顶层画细绿弧线，标“持续学习，影响下次判断”。
底部一句：项目理解既包括当次查明，也包括跨任务积累。
准确边界：不是人完全不搜索，不是Agent没有当次理解；不声称训练覆盖人类全部仓库。

下方单独细灰框“查明的机制（简化）”：请求 → 缓存查找；分支“命中” → “返回已有响应”，分支“未命中” → “后续检查与业务处理” → “响应补充区分信息” → “符合条件时写缓存”。注明“前置检查已执行；后续检查可能被跳过”以及“本次只阅读测试，未执行测试”。
末行：“通用先验给切入点，工具返回决定下一步”。严禁将4阶段画成4次工具调用。

这是研究方案机制图，不能假装功能全部实现。上层证据来源，中层经验治理，下层人和Agent两条路径，最底部评估反馈。大约14个节点，细线严谨清晰。

底部两个评估细栏：“Agent：质量不降，端到端 token 稳定节省”“人：理解设计、识别风险、看护长期演进”。

视觉主角是证据如何成为可更新经验，并分流支持两种使用者，不用芯片、放大镜、书本等任何卡通图标。
